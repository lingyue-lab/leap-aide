# LeapAide 发布流程

一次发布如何切割、发布与公告——以及为什么 GitHub Release 页面是更新日志的镜像，而不是同一场发布的第二份描述。

---

## 唯一事实来源

更新日志*就是*发布说明。`CHANGELOG.md` 与 `CHANGELOG.zh-CN.md` 承载每一次发布的精编双语描述，GitHub Release 页面由它们渲染而成——绝不手工撰写。

GitHub 可以根据已合并的 PR 自动生成发布说明。那是 PR 视角、且只有英文：它说的是 PR 叫什么，而不是用户拿到什么。若那样写，发布说明不会提到共享浏览器桌面——那个改动是会话级显示方式的重构，没有任何 PR 标题能承载它。同一场发布的两份手工描述必然漂移；一份从另一份派生出来的描述则不会。

**创建发布时永远不要勾选 "Generate release notes"。** 发布正文由 CI 任务自行发布。

---

## 创建发布版本

### 1. 撰写更新日志条目

变更先积累在 `CHANGELOG.md` 与 `CHANGELOG.zh-CN.md` 的 `## [Unreleased]` 之下。两种语言必须在同一个 PR 中一起修改——否则双语配对门禁会让构建失败。

发布时，在两个文件中同时重命名该小节：

```
## [Unreleased]
```

变为：

```
## [0.2.0] - 2026-12-01
```

若该版本的小节已经存在，把待发布的条目移进去，而不是重命名锚点：更新日志每个版本只有一个小节。同名小节出现两次会让双语配对门禁直接失败——记录按标题路径索引，路径重复即为硬错误；渲染器取第一个匹配项，发布页上只会出现一半内容。

然后重新记录一致性摘要：

```bash
python3 backend/scripts/check_translation_pairing.py --write CHANGELOG.md
```

### 2. 通过 PR 合入

推送分支并向 `main` 发起 PR。`main` 只能经评审到达——不要直接推送到它，也不要直接推送到 `upstream`。

### 3. 打发布标签

```bash
git tag -a v0.2.0 -m "LeapAide v0.2.0"
git push upstream v0.2.0
```

标签要推到承载发布的那个仓库——本 checkout 中是 `upstream`，其中 `origin` 是你的 fork。标签推到 fork 会把镜像发布到 fork 的镜像仓库命名空间（`ghcr.io/<fork-owner>/leap-aide-runtime`），并在 fork 上创建发布页，而更新日志里对外承诺的是 `ghcr.io/lingyue-lab/leap-aide-runtime`。

标签指向的提交已经合入，因此它不会引入未经评审的代码：PR 仍然是进入 `main` 的唯一途径。

标签消息会成为发布标题，因此保持 "LeapAide v0.2.0" 这种形式。轻量标签同样会得到这个标题。

推送标签会触发运行时镜像工作流：它为该标签构建镜像，推送到 GHCR 的 `:<version>` 与 `:latest`，并在镜像进入镜像仓库之后发布 GitHub Release。

### 4. 发布页出现

`publish-release` 任务从更新日志小节渲染双语正文，并为该标签创建发布。它依赖镜像任务，因此发布页绝不会指向尚未发布的镜像。

已存在的发布会被覆盖而不是跳过：更新日志是事实来源，手工编辑过的正文属于漂移，必须被纠正。

## 预览发布说明

打标签之前，先在本地渲染正文：

```bash
python3 scripts/release_notes.py --version 0.2.0
```

正文是中英双语，顶部带可点击切换的头部：`[English] | [中文]`。英文区块默认展开，无需点击即可阅读；中文区块默认收起，点击切换会跳到它的展开条。每种语言的标签是标题而不是粗体：折叠条默认用正文字号，那会让语言入口看着像说明文字上方的题注，而不是它本来的小节标题。

GitHub 会剥掉发布正文中的脚本与样式，因此严格的 tab 组件并不可用——切换由两个可折叠区块加锚点链接构成，这已是静态页面能做到的最接近 toggle 的形态。

正文在发布前会被归一化：一个段落变成一行，列表项把续行收进自己。GitHub 渲染发布正文时开着硬换行——正文里的每个换行都会变成一次换行——所以保留更新日志折行的正文，会在宽一倍的栏里显示成一条窄窄的短行带子。渲染器把散文重新接起来；代码块、表格等结构原样保留。

---

## 发布任务不会做的事

- 它不会根据 PR 生成发布说明，也不会用标签消息当作正文。
- 它不会修改更新日志。找不到版本是错误，而不是编造一个的理由。
- 它不会移动 `:latest` 镜像标签——那是镜像任务的事。

---

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 发布任务报 "no section for version" | 更新日志里没有该版本，或只有一种语言有 | 在两个文件中补上该小节并重新记录摘要 |
| 发布正文为空或只有一种语言 | 小节从错误的文件里抽取 | 检查 `CHANGELOG.md` 与 `CHANGELOG.zh-CN.md` 是否都有该小节 |
| 发布页显示的是自动生成的说明 | 有人在网页端勾选了 "Generate release notes" | 重跑发布任务，或用渲染出的正文替换 |
| `:latest` 镜像标签没有移动 | 镜像任务在推送前就失败了 | 在该次标签运行上重跑 "Re-run all jobs" |
